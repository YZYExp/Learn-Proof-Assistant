# 第03章　看懂证明状态，才知道下一步做什么

交互式证明最重要的反馈，往往不是最终的成功提示，而是中间的证明状态。它告诉你：当前允许使用什么，仍需证明什么，以及有哪些尚未完成的分支。读懂它，才能把“尝试命令”变成有目的的推理。

Lean 通常在信息面板中显示局部上下文和 `⊢` 后的目标；Rocq 通常把局部上下文放在分隔线上方、目标放在下方。界面样式不同，核心结构相近：一个目标连同它可以使用的局部材料。[资料：Lean《Tactics》§5.1](https://lean-lang.org/theorem_proving_in_lean4/Tactics/)；[Rocq 9.0《Proof mode》](https://rocq-prover.org/doc/V9.0.0/refman/proofs/writing-proofs/proof-mode.html)。

## 3.1 三行状态的含义

设状态可以简记为：

```text
P Q : Prop
hP : P
hPQ : P → Q
⊢ Q
```

第一行声明两个命题。第二行给出 `P` 的证据。第三行给出从 `P` 到 `Q` 的转换。最后一行才是当前欠缺的证明：需要构造 `Q`。

这里可以直接使用 `hPQ hP`。若写成策略，Lean 为 `exact hPQ hP`，Rocq 为 `exact (hPQ hP).`。`exact` 的意思是提交一份能够完整满足当前目标的证据。它不是要求“目标与证据文本长得一样”，系统会按类型规则比较它们。

另一条路线是先 `apply hPQ`，把目标变成 `P`，再用 `hP` 完成。这个过程适合反向阅读：要得到 `Q`，可以利用一个以 `Q` 为结果的定理；该定理要求 `P`，于是先补上 `P`。

## 3.2 引入前提没有凭空增加事实

当目标是 `P → Q`，我们可以暂时接收一个 `P` 的证据，再证明 `Q`。Lean 用 `intro hP`，Rocq 用 `intro hP.`。执行后，`hP : P` 出现在上下文，目标变为 `Q`。

这并非把未知的 `P` 擅自宣布为真。我们正在建立的是条件结论：如果有人提供 `P`，这份证明将如何得到 `Q`。在完整证明项中，它表现为一个接收参数的函数。若最终想无条件得到 `Q`，调用这个函数时仍需提供真实的 `P` 证据。

同理，证明“对任意自然数 `n`，性质 `R n` 成立”时，引入 `n` 意味着考虑任意对象，不能偷偷把它限定成零。证明过程中若只解决了零的情况，便还没有完成全称命题。

## 3.3 子目标增加，不一定是退步

面对 `P ∧ Q`，可以把任务拆成证明 `P` 与证明 `Q`。Lean 使用 `constructor`，Rocq 常使用 `split.`。目标从一个变成两个，但结构更简单：我们已经知道应分别构造什么。

初学者容易只看到当前显示的分支，忘记后面还有分支。应养成检查未完成目标总数的习惯。Lean 中可以用缩进和项目符号组织分支，Rocq 中常用 `-`、`+` 等 bullet；这些结构帮助保持“本段处理哪个义务”的对应关系。

分支的上下文也可能不同。分类讨论某个对象以后，一支拥有的条件不一定出现在另一支。不能因为第一支使用过一个假设，就默认其他支也能使用它。阅读状态时应重新确认当前分支实际列出的材料。

## 3.4 从错误信息判断错在哪一层

证明失败至少可能发生在四个层面：

| 现象 | 首先检查 |
|---|---|
| 名字找不到 | 拼写、导入、命名空间与版本 |
| 类型不匹配 | 证据证明了什么，目标要求什么 |
| 重写没有匹配位置 | 等式方向、表达式形状、隐式参数 |
| 还剩目标 | 是否漏分支、前提或存在见证的性质 |

这张表是一种排查顺序，而非每个错误的固定答案。例如名字找不到可能来自库版本变化，不应该马上改数学陈述；类型不匹配也可能提示把自然数与整数混用了，不能只增加自动化。

一个实用做法是保留最后一个你能解释的状态，撤回后续尝试，然后只推进一步。能明确说出“这一步把什么目标变成了什么目标”，通常比累计更多策略更有帮助。

## 3.5 策略脚本与证据不是同一层

策略负责指导系统构造证明项。一个很短的脚本可能触发复杂搜索，一个很长的脚本也可能只是在逐项组装简单证据。代码行数因此不能直接代表数学难度、检查成本或可靠程度。

Lean 允许在需要一个项的位置用 `by` 进入策略模式；Rocq 常以 `Proof.` 开始交互过程，以 `Qed.` 结束并保存证明。两种语言也都能直接给出证明项。本书使用策略，是为了观察状态变化，不是把策略名称当成推理依据的替代品。

还要辨认开发占位符。Lean 的 `sorry` 和 Rocq 的 `Admitted.` 能让工作暂时继续，但它们没有完成相应证明。存在这类占位时，其他文件能否继续检查，与该结论是否已经获得完整证据，是两件事。Rocq 的 `Abort.` 则是放弃当前证明，并不保存该定理。[资料：Rocq《Proof mode》中的完成与放弃证明命令](https://rocq-prover.org/doc/V9.0.0/refman/proofs/writing-proofs/proof-mode.html)。

## 3.6 试着预报下一步

**练习。** 当前上下文中有 `h : P → Q`，目标为 `Q`。执行 `apply h` 后会发生什么？如果上下文里没有 `P` 的证据，系统应该自动认定 `P` 成立吗？

**参考解答。** 新目标是 `P`。应用定理只是选择了一条完成 `Q` 的路线，没有免除前提。若找不到 `P` 的证据，需要其他论证，或承认目前这条路线尚未完成。系统不应因为结论有用就接受未证前提。

以后每学习一种策略，都可以做相同练习：先写出预计的上下文与目标，再执行并对照。证明状态由此成为检验理解的工具，而不只是报错窗口。
